# 题库导航 · 在线浏览

一个用于浏览 / 记忆题库的静态站点。**一个导航页 + 一个通用查看器**，多套题库各自独立、互不关联。

## 在线访问

启用 GitHub Pages 后访问：

```
https://<你的用户名>.github.io/<仓库名>/
```

## 站点结构

```
.
├── index.html              导航页：自动列出所有题库，点卡片进入
├── viewer.html             通用查看器：viewer.html?p=<题库名>
├── assets/
│   ├── style.css           全站唯一样式（深色/浅色、卡片、高亮、响应式、打印）
│   └── viewer.js           全站唯一逻辑（渲染、搜索、高亮、主题）
├── data/                   构建产物，勿手改
│   ├── manifest.js         题库清单（导航页读取）
│   └── <题库名>.js         每套题库的数据，文件名与 sources/ 里的源文件一致
├── sources/                ← 只管往这里丢 json
│   ├── 隐患判定准则-全题库.json
│   ├── 隐患判定准则-考试版.json
│   └── 危化品应急处置与应急管理.json
├── tools/build.ts          构建脚本
└── deno.json               任务定义
```

**设计要点**：样式和逻辑只有一份，改一次全站生效；每套题库只是一个纯数据文件。
数据存成 `.js`（`window.PAPER = {...}`）而不是 `.json`，用 `<script src>` 加载，
所以 `file://` 双击也能直接打开，不依赖服务器。

## 新增一套题库（两步）

1. 把后台导出的 `data.json` 丢进 `sources/`，**文件名随便起**（中文、空格都行）：

   ```
   sources/消防设施操作员.json
   ```

2. 运行构建：

   ```bash
   deno task build
   ```

完事。导航页上会**自动多出一个叫「消防设施操作员」的按钮**，点击进入浏览。
不需要改任何 HTML / CSS / JS，也不需要维护任何清单文件。

### 命名与排序规则

| 规则 | 说明 |
| --- | --- |
| 文件名 → 题库 id | `sources/消防设施操作员.json` → `data/消防设施操作员.js` |
| 文件名 → 按钮名 | 按钮标题默认就是文件名（去掉 `.json`） |
| 排序 | 按文件名排序（中文按拼音）。想固定顺序可加数字前缀，如 `01-xxx.json` |
| 改名 | 直接重命名 `sources/` 里的文件后重新 build 即可，旧的 `data/*.js` 会被自动清理 |
| 删除 | 从 `sources/` 删掉文件后重新 build，按钮随之消失 |

### 可选：自定义标题与说明

如果不想让按钮直接显示文件名，可以在 json 顶层加两个字段（构建时会读取，其他字段一律不动）：

```json
{
  "title": "消防设施操作员（中级）",
  "sub": "基础理论 · 设施操作 · 维护保养",
  "code": 200,
  "msg": "查询成功",
  "data": [ ... ]
}
```

不加也完全可以，默认就用文件名。

## 功能

- **导航页**：卡片式列出全部题库，显示题数、题型构成、数据批次
- **查看器**：答案直接显示，正确选项绿色高亮 ✓，多选答案形如 `ABCDE（多选）`，判断题选项渲染为 `√ / ×`
- **搜索**：匹配题干 / 选项 / 解析，命中词实时高亮（大小写不敏感），并显示命中题数
- **深色模式**：默认深色，可切换浅色，选择被 localStorage 记住
- **响应式**：手机 / 平板 / 桌面自适应
- **打印友好**：`Cmd+P` 可直接打印成纸质复习材料
- **纯静态零依赖**：不请求任何外部资源，离线可用

## 构建时自动校验

`deno task build` 会逐题检查，有问题会**直接报错并中止**（不会生成错误页面）：

- json 是否合法、是否包含 `data` 数组（丢错文件会立刻提示）
- 题干是否为空、ID 是否重复、题型是否为 `1/2/3`
- 是否缺选项、缺答案
- 判读题是否正好 2 个选项
- 单选题答案是否为单个字母
- **答案字母是否超出选项范围**（例如 4 个选项却给了 `E`）

## 本地预览

**方式一：起本地服务器（推荐，和线上环境一致）**

```bash
cd question-bank
deno task serve          # 默认 http://localhost:8000
PORT=8080 deno task serve  # 换端口
```

然后浏览器打开 **http://localhost:8000/** 即可。按 `Ctrl+C` 停止。

**方式二：直接双击 `index.html`**

不需要任何服务器，`file://` 直接打开就能用（数据用 `<script src>` 加载，不受 CORS 限制）。
缺点是路径里带 `?p=` 的查看器页面在部分浏览器里体验略有差异，正式验证建议用方式一。

## 部署到 GitHub Pages

```bash
git init
git add -A
git commit -m "init: 题库导航站点"
git branch -M main
git remote add origin <仓库地址>
git push -u origin main
```

推送后在仓库 **Settings → Pages** 中设置：

- **Source**: `Deploy from a branch`
- **Branch**: `main` / `/ (root)`

约 1 分钟后即可访问 `https://<用户名>.github.io/<仓库名>/`。

## 数据字段说明

`sources/*.json` 使用后台原始导出格式，构建脚本读取以下字段：

| 原始字段 | 含义 | 产物字段 |
| --- | --- | --- |
| `ID` | 题目 ID | `id` |
| `tq_name` | 题干 | `q` |
| `TQ_TYPE` | 题型：`1` 单选、`2` 多选、`3` 判断 | `type` |
| `xx` | 选项，`~~!!~~` 分隔（顺序即 A/B/C/D/E） | `opts` |
| `BZ_ANSWER` | 答案（多选形如 `A,B,C,D,E`；判断为 `对` / `错`） | `ans` |
| `analysis` | 解析，为空则不显示解析区块 | `exp` |
| `batch` | 数据批次 | `batch` |

题干、选项、解析里的 `\uXXXX` 转义会被自动还原成中文。
